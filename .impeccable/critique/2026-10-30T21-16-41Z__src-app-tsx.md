## Overall Impression
Tyohar AI has an exceptionally high-utility mathematical foundation. Its logic solves genuine pain points that generic LLMs fail at. However, the UI suffers from **information overcrowding, viewport asphyxiation, and aesthetic dissonance**. The layout shell needs to breathe: vertical stacking must be collapsed, state mutations need non-destructive undo safeguards, and the visual mood must shift from "B2B cyber dashboard" to "Ceremonial Mandap Console" with calm, dignified typography.

1. **Fiduciary Transparency & Truth in Badging:** The strict distinction between `"Estimated Market Benchmark (Unconfirmed)"` and emerald `"Verified Vendor Quote"` builds immediate credibility.

3. **Tactile Spring Rolling Counters:** `<AnimatedCurrency />` and `<AnimatedNumber />` deliver reassuring, lively visual feedback whenever guest counts or priority weights shift.

## Priority Issues (P0–P3)

### [P0] Irreversible State Mutations with No "Undo/Revert" & No Local Persistence
- **Locations:** `src/App.tsx:47`, `ChaosMutatorBar.tsx:108-125`, `BudgetDashboard.tsx:68-81`
- **Why it matters:** When users test "+20% Cost Overrun" or run a natural-language what-if scenario, the active plan is mutated in-place in React state without an "Undo Mutation" button. Reloading the page loses all edits because state is held purely in memory. Stressed hosts hesitate to experiment for fear of breaking their work.
- **Fix:** 
  1. Add an in-memory mutation history stack with an instant `"Undo Last Change"` banner.
  2. Autosave `currentPlan` to `localStorage` with a visible `"Autosaved Draft"` indicator.
- **Suggested Command:** `/impeccable harden`

### [P1] Viewport Asphyxiation from Triple-Stacked Sticky Headers
- **Locations:** `src/App.tsx:331-344`, `ChaosMutatorBar.tsx:200-260`, `Primitives.tsx: GuidedPageHero`
- **Why it matters:** On standard laptop viewports (1366x768 or 1080p), the combination of the mobile bar + sticky `ChaosMutatorBar` (56px) + gigantic `GuidedPageHero` banner (240px tall) pushes the actual data tables and budget ledgers 350px down, forcing constant scrolling.
- **Fix:** 
  1. Re-architect the layout shell: integrate the `⌘K What-If` trigger directly into the sidebar header or main view header.
  2. Condense `GuidedPageHero` into a compact single-line page title with an inline popover for tips.
- **Suggested Command:** `/impeccable layout`

### [P2] Alienating Technoid Jargon in Place of Culturally Reassuring Gravitas
- **Locations:** `OverviewDashboard.tsx:398`, `DependencyTimeline.tsx:164, 391`, `BudgetDashboard.tsx:325`
- **Why it matters:** Prominent user badges boast *"Topological sorting active • Zero deadlocks"*, *"Kahn's Algorithm Active"*, and *"Surgical Trade-Off Resolver"*. These communicate to developer evaluators, not to families planning weddings. Deficit alerts sound punitive rather than supportive.
- **Fix:** Reframe technical claims into host benefits: *"Event Sequence Verified • No Scheduling Conflicts"* and *"Priority Shield: Safeguarding your Food & Venue"*.
- **Suggested Command:** `/impeccable clarify`

### [P3] Dead Code & Navigation IA Fragmentation
- **Locations:** `src/components/Header.tsx` (L1-312), `src/App.tsx:96-127`, `DependencyTimeline.tsx:395`
- **Why it matters:** `Header.tsx` is an orphaned 312-line component completely ignored by `App.tsx`'s studio view, yet containing duplicate preset selectors and export logic. In `DependencyTimeline.tsx`, prerequisite dependencies are displayed as raw code keys (`t1, t2`) instead of human-readable task titles.
- **Fix:** Delete `Header.tsx` completely. In `DependencyTimeline.tsx`, map task dependency IDs to task titles.
- **Suggested Command:** `/impeccable distill`
